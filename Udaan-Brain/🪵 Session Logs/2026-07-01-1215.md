## 🎯 Goal
Kick off M1 "Touch Flight Toy": make flying feel good on a touchscreen in single-player, and stand up a simple drone-racing circuit (circular hoop gates) to test feel against.

## 🕵️ Assumptions Going In
- Touch was undefined; the 5-axis canonical scheme ([[controller-map]]) is the target to mirror on touch.
- Offline single-player is acceptable for the feel gate (netcode parked per M1).
- Drone_Player.prefab has Rigidbody + collider and can be Instantiated offline (NetworkBehaviours run as MonoBehaviours when not spawned).

## ⚙️ Execution Mode
BFS — built an input abstraction first, then touch + gamepad sources, then refactored the controller/camera, then the racing circuit, then docs.

## 📝 Actions Log
- Added device-agnostic input layer in `Assets/Scripts/Input/`: `FlightInputState` (struct + `IFlightInput`), `GamepadFlightInput` (legacy axis reader), `TouchFlightHUD` (runtime canvas, no prefab wiring), `FlightInputRouter` (merges sources, auto-provisions).
- `TouchFlightHUD`: two schemes with in-game toggle — **TwinStick** (L=strafe/altitude, R=absolute aim) and **MoveAndDrag** (L=move, R=swipe-to-aim rate). Persistent throttle slider, hold-BRAKE, VIEW toggle. Reads raw `Input.touches` by screen region (no EventSystem); regions/feel inspector-exposed.
- `DroneFlightController`: now reads `FlightInputRouter` instead of `Input.GetAxis`; added `HasControl()` (`!IsSpawned || IsOwner`) so it flies offline; added air-brake + optional auto-level assist. Preserved hover physics + class-data path.
- `CameraController`: offline-friendly (claims camera when no NGO session), defaults to chase cam, exposed `ToggleView()`, null-safe mount fallback.
- Racing in `Assets/Scripts/Racing/`: `RaceGate` (hoop pass trigger + next-gate highlight), `RaceManager` (ordered gates, lap/best/total timing, HUD readout), `RaceTrackGenerator` (procedural torus hoops in a circle + ground plane), `SinglePlayerBootstrap` (offline: builds track + spawns drone at start line).

## 🎮 Playtest tuning (session-028) — PC + controller feedback
Feedback: track/placement great; too slow; controls very intuitive (only used right-stick aim + slider, never left stick); struggled reversing after a missed gate.
- **Stick swap:** LEFT stick now aims (yaw/pitch), RIGHT translates (strafe/altitude) — gamepad (`GamepadFlightInput`) + touch (`TouchFlightHUD.leftStickAims`).
- **Throttle:** center-detent slider, `thrust` −1..1 (up = fwd, down = reverse); persistent by default, optional `throttleSelfCenters`. Gamepad `thrust` = RT − LT.
- **Speed:** `thrustMultiplier` ≈ 3× top speed, `reverseScale` 0.6, `steeringMultiplier` 1.5 (new serialized fields → prefab picks up defaults; class-data drag still governs terminal velocity).
- **Missed gate:** no code change — the missed gate stays the green target and only counts in order, so the intended recovery is to loop back through it; reverse retained for other modes.
- **Warnings fixed:** guarded velocity sets against kinematic Rigidbody (prefab rb starts kinematic under NGO; now set non-kinematic on spawn).

## 🔫 Weapons pass v1 (session-031)
Pivot: movement good enough; weapons + **aim** are the make-or-break. User direction: nose-aim default + right-stick free-aim (recenters on release) toggled by an **aim-mode switch button**; two fire buttons; bullets + dumb rockets; everything tunable ("find the default by testing"). Lock-on (tap-to-lock on touch) + easy-mode hybrid = later.
- Input: `FlightInputState` gained `aimX/aimY` + `firePrimary/fireSecondary`; `FlightInputRouter` gained `AimMode` (NoseAim/FreeAim) + `CycleAim()` + `Last`.
- Aim-mode switch repurposes the right stick: NoseAim → strafe/altitude; FreeAim → reticle offset (cone `maxAimAngle`), crosshair follows.
- `DroneWeapon` rewritten: router-driven, pooled procedural bullets + splash rockets, offline-friendly.
- `TargetHealth` offline-friendly; `SinglePlayerBootstrap` spawns procedural dummies to shoot.
- **Test focus:** does aiming feel good? Tune `maxAimAngle`, fire rates, speeds; then decide default aim mode.
